# Shared Studio core

This directory contains one copied NovaStore Studio v4 editor and its existing presentation renderer. `source-provenance.json` records every original copied source file, size and SHA-256 before the integration changes. The reference directory is not changed. Admin and Seller load the same built iframe module; the shells do not implement another editor.

Build with `npm ci --ignore-scripts` then `npm run build`. The output is `dist/`, served only by the opt-in Theme Platform route at `/theme-studio/`. `preview.html` uses the same entry point and a readonly renderer mode. There are no credentials in either URL. Same-origin frames isolate module state and styles, not hostile code. Preserve the existing Admin and storefront frame-denial policy; only the dedicated /theme-studio/ and /studio-pro/ routes can be framed by the same origin.

`src/studio-integration/platform-bridge.js` exports `createPlatformClient`, `mountPlatformStudio`, `capabilityFlags`, and `documentOverrides`. `mountPlatformStudio` receives an authenticated `editor-context` or `seller-preview` response with server scope, actor, available channels, immutable base, merged document, revision, capabilities and policy revision. The server remains the authority for every read and mutation. Admin-as-Seller uses the same module with the server's computed seller projection and readonly transport. Policy refresh occurs on focus and every 15 seconds. Errors or actor, tenant, store, assignment, draft, version, mode or channel identity changes close access and existing ports. Document revision changes remain subject to CAS so unsaved work is not silently replaced. An optional AbortSignal cancels initial image loading and iframe mounting; failure and disposal revoke every created Blob URL. Packaged image caches include immutable version identity, allowing Web and app versions to use different bytes under the same package key.

The full original authoring entry is now built separately at `/studio-pro/`, with the same `Studio.jsx` and all original local tools. Its existing seller-offers section receives the real embedded management component. See [WORKSHOP.md](WORKSHOP.md) for authentication, asset closure, local-versus-server data boundaries and build instructions. The optional module API `externalShell`, `initialSection` and `navigate(section)` remains a presentation adapter; it is not the full authoring entry. The active server editor is now constrained by the selected immutable presentation. Classic exposes only the supported fixed-slot, appearance and visual controls; arbitrary block composition, Seasons application, page/template/menu redesign are unavailable in this renderer. The general campaign import adapter remains independently tested, while the complete original Seasons library and package editor remain in the local authoring workspace. The original local calendar, local publication history, reset/import and workshop persistence are not server delivery features; server catalog/offers/history use authenticated adapters. Merely preserving a source module does not establish working server parity.

The original 108 authored campaign packages and 130 raster files (21,150,592 bytes) are recorded in `bundled-assets-provenance.json`. Vite creates an exact build-time image allowlist for local gallery display. Applying a package or saving one to the document first normalizes that newly authored package, checks canonical product/category/target identity, rejects schedules, then uploads referenced raster bytes through the scoped asset API. Only returned `asset:<UUID>` references enter the draft. The immutable base and server validator are unchanged. If any image fails or the operation is cancelled, no partial package is committed; already uploaded images can remain as unattached scoped assets. Local raster upload previews may temporarily use bounded PNG/JPEG/WebP data URLs inside the package editor, but server documents still reject these and application converts them to scoped assets. Original vector/shape composition stays in its typed, validated representation.

The portable document is `{schemaVersion:2, studio:<complete native v4 document>}`. Typed partial overrides are `{studio:{...}}`; object fields merge and arrays replace. The immutable base is never mutated. `services/themePlatformStudioDocument.js` uses the copied core normalizer as a strict canonical validator: missing defaults, unknown fields, coercions, arbitrary image URLs, raw markup, unsafe trees and excessive size are rejected. Images are internal `package:theme-assets/...` or `asset:<UUID>` references. Authenticated shell requests retrieve bytes as Blob URLs held only in memory. No malformed server document is filled from a demo.

`document-capabilities.js` is shared by the client edit guard and server native-document adapter. UI controls are guidance; this guard is not backend authorization evidence. Server role, membership, service state, capabilities, policy revision, draft CAS and asset scope must also pass.

The trusted Classic renderer reuses the original Theme Kit templates and styles, with canonical products, variants, reviews, answered questions and quote totals. See [THEME_KIT.md](THEME_KIT.md) for source identity, supported edits and precise limits. Unknown or legacy presentation descriptors show an unsupported message; they are never rendered as an unrelated generic theme. This delivery registers only Classic web. Other gallery themes and app-channel presentations are not claimed as canonical runtime integrations. Reference thumbnails may be stale and must retain that label.

The canvas also has a separate **Çalışma taslağı** mode: each edit sends a complete typed document only through the scoped in-memory bridge into the existing readonly preview iframe. It never saves a database revision or a server snapshot. The shared pure validator is used by both this bridge/session and the server adapter. Documents arriving through trusted iframe ports are cloned into the receiving realm before strict plain-object validation; the validator itself is not relaxed. Tenant, store, channel, page and monotonically increasing request sequence checks reject stale/foreign updates. The **Sunucu önizlemesi** tab still requires an explicitly saved draft and retains the real immutable snapshot flow. Neither tab claims a live publication.

The Classic preview uses the original `VisualEditingLayer` directly inside the same frame for text/container selection and icon placement. Browse/edit toggling retains the current route. Canonical product/category links remain in the trusted Classic renderer. Transient arbitrary block ordering is not advertised for the fixed Classic layout. Account/cart/support never fabricate customer sessions or orders. Source and unit checks require separate real browser evidence.

Tests: `node --test tests/*.test.mjs` from this directory includes 25 session/lifecycle tests, eight campaign-import tests, twelve working-preview tests, eight workshop-entry/asset tests and eleven trusted Classic tests (64 total). One campaign test covers 648 authored combinations (108 packages × two channels × three compositions); these are cases inside one test. Classic tests execute the original host bridge in a VM and also verify source hashes, scoped routes, custom campaign consistency and variant pricing. Repository root native-document, presentation-policy and real HTTP/PostgreSQL suites are separate; consult the final test ledger for their final counts and execution evidence. None of these unit/model counts establishes browser acceptance, deployment or native delivery.
