## Why is this project a good fit?

Use only if the applicant is the maintainer identified in the repository:

> I maintain NovaStore, an MIT-licensed commerce project spanning a Node.js API, web storefront, React admin foundation, and Android client. Its history shows 26 merged maintainer-authored pull requests, security and migration hardening, and CI for backend/storefront, admin, and Android. It is pre-release with no verified adoption metrics. I am applying on its multi-surface scope and the work needed to make it safer and easier to contribute to.

## How will API credits be used?

> I would use API credits for core open-source maintenance: review incoming pull requests against existing API, authorization, and migration contracts; triage and summarize issues; improve regression and security checks; maintain contributor documentation; and prepare reproducible release workflows. These are planned maintainer workflows, not existing automated services. Work would use disposable local data, and a maintainer would review changes before merge or release.

## Anything else we should know?

> NovaStore is an early-stage, primarily maintainer-led project. Its technical value is the integration of commerce API, web, admin, Android, and database-safety work in one MIT-licensed repository. Public adoption is not yet demonstrated: the current snapshot shows zero stars and forks and no versioned release. Support would help the maintainer improve reproducible setup, security and regression coverage, and release readiness. This application does not assume acceptance.
